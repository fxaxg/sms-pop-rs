# 安卓短信验证码 → Mac（同一 Wi-Fi）

本分支在 SmsPop 原项目上增加 macOS 局域网接收。手机使用 SmsForwarder，Mac 无需中转服务器。验证码提取在本机完成。

## 启动 Mac 应用

打开构建输出 `target/release/bundle/macos/SmsPop.app`。首次启动默认进入“网络接收”。关闭设置窗口后应用仍在菜单栏运行；退出请使用菜单栏菜单。

这是供本机测试的开发构建，尚未签名公证，不是正式发布安装包。不要关闭 Gatekeeper 或系统安全保护来运行不信任的下载。

## 配置手机

1. 手机与 Mac 接入同一 Wi-Fi。访客网络或公司网络可能开启设备隔离；同一 Wi-Fi 名称不保证设备互通。
2. Mac 的“网络接收”页选择局域网范围，开启服务，默认端口为 24836。
3. 通过“网卡”选择手机能访问的 Mac IPv4 地址，通常为 `192.168.*` 或 `10.*`。不要选择 `127.0.0.1`、`169.254.*` 或不通的 VPN 地址。
4. 点击 **仅复制接口地址**。它包含随机鉴权令牌，不要把链接发到群聊或公开截图中。
5. 在 [SmsForwarder](https://github.com/pppscn/SmsForwarder) 创建 Webhook 发送通道，填入该地址，方法为 POST，Content-Type 为 `application/x-www-form-urlencoded`。
6. 表单参数填写：

   ```text
   device_name=Android&from=[from]&content=[content]
   ```

   应使用发送器的表单字段/编码功能，确保中文、`&`、`+` 与换行被正确编码。界面和占位符以所安装的 SmsForwarder 版本为准。不要把带“通知正文”示例参数的 GET 测试链接用于 POST。
7. 建立短信转发规则并绑定上述通道；授予短信权限和该手机系统需要的后台运行权限。
8. 先发送一条测试短信，再使用真实收到的验证码检查：Mac 显示通知，点击验证码可以复制。

也可以把不带 token 的接口地址与 `Authorization: Bearer YOUR_TOKEN` 请求头组合使用。凭据只能放在请求头、URL 或请求体三者之一，重复会被拒绝。

## 快捷键填入

在“验证码”页打开辅助功能设置，手动允许 SmsPop；返回后权限状态自动刷新。可复制功能不要求辅助功能授权。

收到验证码后，点击其他应用中的输入框，按 **⌘⇧V 并松开**。快捷键可修改，冲突时显示失败。候选从接收开始保留 120 秒，过期后不会输入；不会自动按回车或提交表单。通知不会主动抢走输入焦点。

系统只能确认输入事件已发送，不能保证所有浏览器和分格验证码控件接受它。无法确认目标可写、权限缺失或控件不兼容时，使用通知中的复制按钮和手动粘贴。

自动复制默认关闭。若想开启，需同时开启“验证码 → 自动复制”和“网络接收 → 允许网络消息自动复制”。

## 连通性与常见问题

- **提示 Listener unavailable**：检查端口是否被占用；更换端口并重新配置手机。
- **手机请求超时**：检查 Mac 防火墙是否允许 SmsPop 入站，排除 VPN 和 Wi-Fi 客户端隔离。应用不会自动改防火墙。
- **401**：令牌不正确、重复提供令牌或已被重置。重新复制接口地址。
- **400 / 415**：检查字段名、请求格式、Content-Type 与表单编码；不支持额外自定义字段。
- **200 duplicate**：消息被去重。测试时换正文，或等待超过 15 秒。带 message_id 的重试在 5 分钟内去重。
- **202 但没弹窗**：表示已进入处理队列，检查通知与验证码过滤设置；它不代表目标输入框已经填入。
- **钥匙串访问失败**：接收不能启用。检查系统对应用访问钥匙串的授权，再重试/重启。不会退化成明文保存凭据。
- **快捷键无效**：检查辅助功能授权、快捷键冲突、是否有未过期验证码，并点击目标输入框。按键后要松开修饰键。
- **换 Wi-Fi 后失效**：重新打开“网卡”刷新地址，选择新 IP 并更新手机通道。
- **休眠/退出期间收不到**：本版不缓存离线消息；重新启动后获取新的验证码。

## 隐私边界

本版为可信局域网 HTTP，随机令牌只提供鉴权，**不提供传输加密**。不要把端口映射到公网。Mac 的令牌在系统钥匙串中，配置文件只保存引用；验证码候选只保存在内存，日志不保存通知正文和验证码。重置令牌会让全部旧链接失效。

## 从源码构建

需要 Node 22、Rust stable（含 rustfmt / clippy）、Apple Command Line Tools。仓库沿用 Node 22 的 TypeScript 测试模式；不要用已移除该模式的 Node 26 直接运行 npm test。

```bash
npm ci
npm test
npm run build
cargo test -p smspop-core -p smspop-app
cargo clippy -p smspop-core -p smspop-app --all-targets -- -D warnings
npm run tauri build -- --config src-tauri/tauri.macos.conf.json --bundles app
```

开发模式：`npm run tauri dev -- --config src-tauri/tauri.macos.conf.json`。

Mac 开发构建不检查或安装原项目的上游更新。Windows 仍按原流程构建，Windows 行为需要对应平台 CI 验证。

## 验收记录原则

自动测试包含参数校验、鉴权、重复消息、真实回环 HTTP、令牌轮换失败、候选有效期、用户输入动作检查及旧设置兼容。模拟 POST 成功不等于手机真机链路通过。

真机验收需手机实际收到一条短信，确认 Mac 通知和复制，再分别在 TextEdit、常用浏览器单输入框中试填；最后测试拒绝辅助功能权限时仍可复制。尚未执行的项目应注明未验证，不写“全部通过”。
